# Data model

The complete model, module by module. Every table states its columns, its keys and its constraints.
Anything that is not obvious carries the reason underneath it.

This replaces the earlier wave, which described thirty minute blocks and an issued certificate. Both
changed in the domain flows session: see `../domain/01-event-storming.md`.

---

## Rules that apply everywhere

**Tenant.** Every table carries `tenant_id varchar(32) NOT NULL` holding the university code, and
every query filters by it. Four tables are exceptions and say so: `identity.tenants`,
`identity.platform_admins`, `skills.catalog_items` when the item is global, and
`skills.categories`.

**Keys.** `uuid`, generated by the application.

**No foreign keys across schemas.** A reference to another module's data is a plain `uuid`. Inside a
schema, foreign keys are declared normally.

**Time.** `timestamptz` in UTC. Plain dates where there is no time.

**Enumerations** are `varchar` with a `CHECK`, not Postgres enum types.

**Audit columns.** `created_at` everywhere; `updated_at` where rows change.

**One credit equals one hour.** Blocks are one hour long.

## `identity`

Who everyone is, which university they belong to, and what that university decides for itself.

### `identity.tenants`

Not tenant scoped: it defines them.

```
id                       uuid          PK
code                     varchar(32)   NOT NULL UNIQUE     -- UPC, travels in every request
name                     varchar(160)  NOT NULL
logo_url                 varchar(512)
primary_color            varchar(16)
secondary_color          varchar(16)
email_domains            text[]        NOT NULL DEFAULT '{}'
minimum_teaching_grade   numeric(4,2)  NOT NULL
timezone                 varchar(64)   NOT NULL DEFAULT 'America/Lima'
status                   varchar(16)   NOT NULL            -- ACTIVE | SUSPENDED
created_at               timestamptz   NOT NULL DEFAULT now()
updated_at               timestamptz   NOT NULL DEFAULT now()

CHECK (status IN ('ACTIVE','SUSPENDED'))
INDEX  USING gin (email_domains)
```

`email_domains` is how a person is routed to their university before they have an account.
`timezone` matters because every block is stored in UTC and shown in the university's local time.

### `identity.platform_admins`

Not tenant scoped, by definition: this is the only role that crosses universities, and the one that
must never read academic data.

```
id           uuid          PK
email        varchar(160)  NOT NULL UNIQUE
full_name    varchar(160)  NOT NULL
status       varchar(16)   NOT NULL        -- ACTIVE | DISABLED
created_at   timestamptz   NOT NULL DEFAULT now()
```

Kept apart from `users` on purpose. If administrators lived in the same table as students, every
query over students would have to remember to exclude them, and the privacy boundary would depend on
a `WHERE` clause.

### `identity.users`

Students and coordinators. Both belong to exactly one university.

```
id                  uuid          PK
tenant_id           varchar(32)   NOT NULL
role                varchar(16)   NOT NULL    -- STUDENT | COORDINATOR
email               varchar(160)  NOT NULL
student_code        varchar(32)               -- NULL for coordinators
full_name           varchar(160)  NOT NULL
career              varchar(160)
current_term        varchar(16)
photo_url           varchar(512)
bio                 varchar(500)
status              varchar(16)   NOT NULL    -- PENDING | ACTIVE | RESTRICTED
onboarding_step     varchar(32)               -- NULL once finished
activated_at        timestamptz
created_at          timestamptz   NOT NULL DEFAULT now()
updated_at          timestamptz   NOT NULL DEFAULT now()

UNIQUE (tenant_id, email)
UNIQUE (tenant_id, student_code)
CHECK  (role IN ('STUDENT','COORDINATOR'))
CHECK  (status IN ('PENDING','ACTIVE','RESTRICTED'))
CHECK  (role = 'COORDINATOR' OR student_code IS NOT NULL)
```

No password column: there are no passwords in this product. `full_name`, `career` and `current_term`
come from the academic system and are not editable in Ayni.

### `identity.access_links`

The magic link. One row per request, single use.

```
id             uuid          PK
tenant_id      varchar(32)               -- NULL for a platform administrator
email          varchar(160)  NOT NULL
purpose        varchar(24)   NOT NULL    -- ACTIVATION | LOGIN | COORDINATOR_INVITE
token_hash     varchar(64)   NOT NULL UNIQUE
expires_at     timestamptz   NOT NULL
consumed_at    timestamptz
requested_ip   varchar(45)
created_at     timestamptz   NOT NULL DEFAULT now()

INDEX (email, purpose) WHERE consumed_at IS NULL
```

The token is stored **hashed**. A leaked database must not hand anybody a working key to every
mailbox. It expires in minutes and is invalidated on use; the session it creates is what lasts.

### `identity.user_sessions`

```
id            uuid          PK
tenant_id     varchar(32)
user_id       uuid                      -- NULL when it belongs to an administrator
admin_id      uuid
token_hash    varchar(64)   NOT NULL UNIQUE
expires_at    timestamptz   NOT NULL
revoked_at    timestamptz
created_at    timestamptz   NOT NULL DEFAULT now()

CHECK (num_nonnulls(user_id, admin_id) = 1)
```

Long lived on purpose: if the session were short, every day would start by waiting for an email.

### `identity.academic_records`

What the academic system says the student approved. A copy, refreshed, never edited here.

```
id            uuid          PK
tenant_id     varchar(32)   NOT NULL
user_id       uuid          NOT NULL REFERENCES identity.users(id)
course_code   varchar(32)   NOT NULL
course_name   varchar(160)  NOT NULL
grade         numeric(4,2)  NOT NULL
term          varchar(16)   NOT NULL
synced_at     timestamptz   NOT NULL DEFAULT now()

UNIQUE (tenant_id, user_id, course_code, term)
INDEX  (tenant_id, user_id)
```

### `identity.credit_policies`

What a university gives its students, and for how long it lasts.

```
id                  uuid          PK
tenant_id           varchar(32)   NOT NULL
kind                varchar(16)   NOT NULL   -- BASELINE | TARGETED
credits_amount      integer       NOT NULL
validity_days       integer       NOT NULL   -- how long the granted credits last
target_rule         jsonb                    -- who qualifies, NULL for BASELINE
valid_from          date          NOT NULL
superseded_at       timestamptz
created_by_admin    uuid
created_by_user     uuid
created_at          timestamptz   NOT NULL DEFAULT now()

CHECK (kind IN ('BASELINE','TARGETED'))
CHECK (credits_amount > 0 AND validity_days > 0)
CHECK (num_nonnulls(created_by_admin, created_by_user) = 1)
INDEX (tenant_id, kind) WHERE superseded_at IS NULL
```

`validity_days` replaces any notion of an academic term. Expiry is a date computed when the credits
are granted, so a student can use the platform during holidays without losing what they were given.

A policy is never updated: the old row gets `superseded_at` and a new one is inserted. The
administrator creates the first one when opening the university; the coordinator supersedes it
later. That is why the author can be either.

## `skills`

The catalogue and who is allowed to teach what.

### `skills.categories`

Global. Technology, university courses, languages, design.

```
id           uuid          PK
name         varchar(80)   NOT NULL UNIQUE
sort_order   smallint      NOT NULL DEFAULT 0
```

### `skills.catalog_items`

One table for two kinds of thing, told apart by `scope`.

```
id             uuid          PK
scope          varchar(16)   NOT NULL    -- GLOBAL | UNIVERSITY
tenant_id      varchar(32)               -- NULL when GLOBAL
category_id    uuid          NOT NULL REFERENCES skills.categories(id)
name           varchar(160)  NOT NULL
description    varchar(500)
course_code    varchar(32)               -- only for UNIVERSITY items
status         varchar(16)   NOT NULL    -- ACTIVE | RETIRED
created_at     timestamptz   NOT NULL DEFAULT now()

CHECK  (scope IN ('GLOBAL','UNIVERSITY'))
CHECK  ((scope = 'GLOBAL') = (tenant_id IS NULL))
CHECK  (scope = 'GLOBAL' OR course_code IS NOT NULL)
UNIQUE (tenant_id, course_code)
INDEX  (tenant_id, status)
```

Tools ship with Ayni and are the same everywhere; courses belong to the university that teaches
them. A student sees the global items plus their own university's, which is one condition in the
query and not two tables to join.

The third `CHECK` is what keeps a global item from ever being assigned to a university, which would
quietly make it invisible to everyone else.

### `skills.offered_skills`

What a tutor is enabled to teach.

```
id                  uuid          PK
tenant_id           varchar(32)   NOT NULL
tutor_id            uuid          NOT NULL
catalog_item_id     uuid          NOT NULL REFERENCES skills.catalog_items(id)
status              varchar(16)   NOT NULL   -- PENDING | ENABLED | REJECTED | WITHDRAWN
accreditation_path  varchar(24)              -- ACADEMIC_RECORD | REVIEWED_EVIDENCE
accredited_grade    numeric(4,2)             -- the grade that enabled it, when applicable
enabled_at          timestamptz
created_at          timestamptz   NOT NULL DEFAULT now()
updated_at          timestamptz   NOT NULL DEFAULT now()

UNIQUE (tenant_id, tutor_id, catalog_item_id)
CHECK  (status IN ('PENDING','ENABLED','REJECTED','WITHDRAWN'))
CHECK  (status <> 'ENABLED' OR accreditation_path IS NOT NULL)
INDEX  (tenant_id, catalog_item_id) WHERE status = 'ENABLED'
```

A university course reaches `ENABLED` on its own when the grade clears the threshold. A global tool
can only reach it through reviewed evidence, because no academic record can vouch for it.

`accredited_grade` is copied rather than looked up: the threshold may change later, and what
justified the decision at the time must remain readable.

### `skills.validation_requests`

```
id                  uuid          PK
tenant_id           varchar(32)   NOT NULL
offered_skill_id    uuid          NOT NULL REFERENCES skills.offered_skills(id)
student_note        varchar(1000)
status              varchar(16)   NOT NULL   -- SUBMITTED | APPROVED | REJECTED
reviewed_by         uuid                     -- a coordinator of the same university
reviewed_at         timestamptz
decision_reason     varchar(500)
created_at          timestamptz   NOT NULL DEFAULT now()

CHECK (status IN ('SUBMITTED','APPROVED','REJECTED'))
CHECK (status = 'SUBMITTED' OR (reviewed_by IS NOT NULL AND reviewed_at IS NOT NULL))
INDEX (tenant_id, status) WHERE status = 'SUBMITTED'
```

### `skills.evidence_files`

```
id                     uuid          PK
tenant_id              varchar(32)   NOT NULL
validation_request_id  uuid          NOT NULL REFERENCES skills.validation_requests(id)
file_name              varchar(255)  NOT NULL
storage_key            varchar(512)  NOT NULL
content_type           varchar(100)  NOT NULL
size_bytes             bigint        NOT NULL
uploaded_at            timestamptz   NOT NULL DEFAULT now()
```

The file itself lives in object storage; the database keeps the pointer.

### `skills.learning_interests`

What a student wants to receive, which drives the recommendations on the portal.

```
id                uuid          PK
tenant_id         varchar(32)   NOT NULL
student_id        uuid          NOT NULL
catalog_item_id   uuid          NOT NULL REFERENCES skills.catalog_items(id)
created_at        timestamptz   NOT NULL DEFAULT now()

UNIQUE (tenant_id, student_id, catalog_item_id)
```

## `booking`

When a tutor is free, and the reservations over that time.

### `booking.availability_patterns`

```
id               uuid          PK
tenant_id        varchar(32)   NOT NULL
tutor_id         uuid          NOT NULL
day_of_week      smallint      NOT NULL   -- 1 = Monday
starts_at_time   time          NOT NULL
ends_at_time     time          NOT NULL
valid_from       date          NOT NULL
valid_until      date
created_at       timestamptz   NOT NULL DEFAULT now()

CHECK (day_of_week BETWEEN 1 AND 7)
CHECK (ends_at_time > starts_at_time)
INDEX (tenant_id, tutor_id)
```

Availability belongs to the tutor, never to a skill. Being free on Monday at five means being free:
any enabled skill can be taught in that hour.

### `booking.availability_exceptions`

```
id               uuid          PK
tenant_id        varchar(32)   NOT NULL
tutor_id         uuid          NOT NULL
exception_date   date          NOT NULL
starts_at_time   time
ends_at_time     time
kind             varchar(8)    NOT NULL   -- ADD | REMOVE
created_at       timestamptz   NOT NULL DEFAULT now()

CHECK (kind IN ('ADD','REMOVE'))
INDEX (tenant_id, tutor_id, exception_date)
```

A `REMOVE` without times covers the whole day.

### `booking.availability_pauses`

```
id          uuid          PK
tenant_id   varchar(32)   NOT NULL
tutor_id    uuid          NOT NULL
starts_on   date          NOT NULL
ends_on     date          NOT NULL
created_at  timestamptz   NOT NULL DEFAULT now()

CHECK (ends_on >= starts_on)
```

### `booking.hour_blocks`

The generated units of one hour. This is what a search returns and what a booking takes.

```
id            uuid          PK
tenant_id     varchar(32)   NOT NULL
tutor_id      uuid          NOT NULL
starts_at     timestamptz   NOT NULL
ends_at       timestamptz   NOT NULL
status        varchar(16)   NOT NULL   -- AVAILABLE | HELD | BOOKED | RELEASED
held_by       uuid                     -- student holding it, while status = HELD
held_until    timestamptz              -- when the hold expires, while status = HELD
booking_id    uuid                     -- set while BOOKED
pattern_id    uuid          REFERENCES booking.availability_patterns(id)
version       bigint        NOT NULL DEFAULT 0
created_at    timestamptz   NOT NULL DEFAULT now()

UNIQUE (tenant_id, tutor_id, starts_at)
CHECK  (status IN ('AVAILABLE','HELD','BOOKED','RELEASED'))
CHECK  ((status = 'BOOKED') = (booking_id IS NOT NULL))
CHECK  ((status = 'HELD') = (held_until IS NOT NULL AND held_by IS NOT NULL))
INDEX  (tenant_id, starts_at) WHERE status = 'AVAILABLE'
INDEX  (held_until) WHERE status = 'HELD'
```

`UNIQUE (tenant_id, tutor_id, starts_at)` stops a tutor from being in two places at once. `version`
is the optimistic lock: when two students confirm the same hour at the same moment, one update finds
a changed version and loses. Map it with `@Version`.

**The hold.** Choosing an hour takes it out of circulation before the student confirms, so that
nobody else can take it while they are writing what they need help with. The block moves to `HELD`
with the student who holds it and a deadline, and confirming turns it into `BOOKED`.

Without this, two students can be filling in the same confirmation screen and one of them loses the
booking after having written everything, which is the worst possible moment to find out.

A scheduled job returns expired holds to `AVAILABLE`. It runs outside any request, so it has no
tenant of its own: it iterates the universities and wraps each turn in `TenantContext.runAs`. The
partial index on `held_until` is what keeps that job cheap.

### `booking.bookings`

A booking covers one or more **consecutive** hours with the same tutor.

```
id                  uuid          PK
tenant_id           varchar(32)   NOT NULL
student_id          uuid          NOT NULL
tutor_id            uuid          NOT NULL
catalog_item_id     uuid          NOT NULL
starts_at           timestamptz   NOT NULL
ends_at             timestamptz   NOT NULL
hours               smallint      NOT NULL
credits_charged     integer       NOT NULL
need_description    text          NOT NULL
status              varchar(16)   NOT NULL   -- CONFIRMED | CANCELLED | COMPLETED | NO_SHOW
cancelled_by        varchar(16)              -- STUDENT | TUTOR | SYSTEM
cancelled_at        timestamptz
cancelled_late      boolean                  -- within 12 hours of the start
cancellation_reason varchar(500)
created_at          timestamptz   NOT NULL DEFAULT now()
updated_at          timestamptz   NOT NULL DEFAULT now()

CHECK (status IN ('CONFIRMED','CANCELLED','COMPLETED','NO_SHOW'))
CHECK (hours >= 1 AND credits_charged = hours)
CHECK (ends_at > starts_at)
CHECK (status <> 'CANCELLED' OR (cancelled_by IS NOT NULL AND cancelled_at IS NOT NULL))
INDEX (tenant_id, student_id, starts_at DESC)
INDEX (tenant_id, tutor_id, starts_at DESC)
```

`credits_charged = hours` is the pricing rule written as a constraint: one credit, one hour.

Cancelling always refunds the student. `cancelled_late` records whether it happened inside the
twelve hour window, which is the same deadline US05 already gives the student. A tutor who removes
availability over a confirmed booking is cancelling that session, and it is recorded against them.

### `booking.tutor_reliability`

What a tutor's record looks like, kept as facts rather than as a score.

```
id             uuid          PK
tenant_id      varchar(32)   NOT NULL
tutor_id       uuid          NOT NULL
booking_id     uuid          NOT NULL REFERENCES booking.bookings(id)
kind           varchar(24)   NOT NULL   -- LATE_CANCELLATION | NO_SHOW
occurred_at    timestamptz   NOT NULL DEFAULT now()

UNIQUE (booking_id, kind)
INDEX  (tenant_id, tutor_id)
```

One row per incident, never a counter. A counter loses the story and cannot be audited.

## `sessions`

The live meeting and the evidence that it really happened.

### `sessions.sessions`

```
id                  uuid          PK
tenant_id           varchar(32)   NOT NULL
booking_id          uuid          NOT NULL UNIQUE
student_id          uuid          NOT NULL
tutor_id            uuid          NOT NULL
scheduled_start     timestamptz   NOT NULL
scheduled_end       timestamptz   NOT NULL
room_name           varchar(120)  NOT NULL UNIQUE
started_at          timestamptz
ended_at            timestamptz
status              varchar(24)   NOT NULL   -- SCHEDULED | IN_PROGRESS | COMPLETED |
                                             -- UNVERIFIED | ABANDONED
created_at          timestamptz   NOT NULL DEFAULT now()

CHECK (status IN ('SCHEDULED','IN_PROGRESS','COMPLETED','UNVERIFIED','ABANDONED'))
INDEX (tenant_id, scheduled_start)
```

`room_name` is the identifier handed to the video service, unguessable so that a stranger holding a
link cannot walk in.

`UNVERIFIED` is the state of a session that took place but failed the presence check below.

### `sessions.participations`

```
id                    uuid          PK
tenant_id             varchar(32)   NOT NULL
session_id            uuid          NOT NULL REFERENCES sessions.sessions(id)
user_id               uuid          NOT NULL
role                  varchar(8)    NOT NULL   -- STUDENT | TUTOR
joined_at             timestamptz
left_at               timestamptz
connected_seconds     integer       NOT NULL DEFAULT 0

UNIQUE (session_id, user_id)
CHECK  (role IN ('STUDENT','TUTOR'))
```

`connected_seconds` is what the real duration is measured against, and one of the signals the audit
looks at.

### `sessions.presence_checks`

The five minute code. This is the anti fraud mechanism.

```
id             uuid          PK
tenant_id      varchar(32)   NOT NULL
session_id     uuid          NOT NULL REFERENCES sessions.sessions(id)
user_id        uuid          NOT NULL
code_hash      varchar(64)   NOT NULL
issued_at      timestamptz   NOT NULL DEFAULT now()
expires_at     timestamptz   NOT NULL
confirmed_at   timestamptz
attempts       smallint      NOT NULL DEFAULT 0

UNIQUE (session_id, user_id)
CHECK  (attempts <= 5)
```

Five minutes after the session starts, each participant receives a six digit code by email and has
to type it into the platform. Whoever is not actually in the session does not have the code, which
is why this prevents the fraud instead of detecting it afterwards.

The code is stored hashed, attempts are capped, and it expires.

> **Decision for you.** What happens when somebody does not confirm. My proposal: the session ends
> as `UNVERIFIED`, **the tutor does not earn credits**, the student is refunded, and the audit is
> notified. Earned credits are the ones that back a recognition request, so granting them without
> proof of presence would empty the mechanism of meaning. The harsher alternative, treating it as a
> no show, punishes somebody whose email simply did not arrive.

### `sessions.whiteboards`

```
id             uuid          PK
tenant_id      varchar(32)   NOT NULL
session_id     uuid          NOT NULL UNIQUE REFERENCES sessions.sessions(id)
content        jsonb         NOT NULL DEFAULT '{}'
has_activity   boolean       NOT NULL DEFAULT false
updated_at     timestamptz   NOT NULL DEFAULT now()
```

Kept so that the student can review it afterwards and download it. `has_activity` answers, cheaply,
whether anything was drawn at all, which the audit uses.

### `sessions.support_materials`

```
id             uuid          PK
tenant_id      varchar(32)   NOT NULL
session_id     uuid          NOT NULL REFERENCES sessions.sessions(id)
summary        text          NOT NULL
suggestions    jsonb
generated_at   timestamptz   NOT NULL DEFAULT now()
```

Generated from the need description so the tutor arrives prepared. Belongs to a later iteration; the
table is here because the session it hangs from is modelled now.

## `wallet`

Credits: where they came from, when they die, and a history that cannot be rewritten.

### `wallet.credit_accounts`

```
id           uuid          PK
tenant_id    varchar(32)   NOT NULL
user_id      uuid          NOT NULL
created_at   timestamptz   NOT NULL DEFAULT now()

UNIQUE (tenant_id, user_id)
```

No balance column. The balance is the sum of what is left in the groups below.

### `wallet.credit_lots`

Credits arrive in groups, because the group is what carries the origin and the expiry.

```
id                 uuid          PK
tenant_id          varchar(32)   NOT NULL
account_id         uuid          NOT NULL REFERENCES wallet.credit_accounts(id)
credit_type        varchar(16)   NOT NULL   -- SEED | ALLOCATED | EARNED | PURCHASED
original_amount    integer       NOT NULL
remaining_amount   integer       NOT NULL
expires_at         timestamptz              -- only for SEED and ALLOCATED
source_type        varchar(24)   NOT NULL   -- POLICY | SESSION | PURCHASE | REFUND
source_id          uuid
created_at         timestamptz   NOT NULL DEFAULT now()

CHECK (credit_type IN ('SEED','ALLOCATED','EARNED','PURCHASED'))
CHECK (original_amount > 0)
CHECK (remaining_amount BETWEEN 0 AND original_amount)
CHECK ((expires_at IS NULL) = (credit_type IN ('EARNED','PURCHASED')))
INDEX (tenant_id, account_id, expires_at) WHERE remaining_amount > 0
```

The last `CHECK` is the rule of the product written where it cannot be broken: only what the
university grants expires. What you earned and what you paid for are yours.

Spending takes from the group closest to expiring. A refund returns the credits to the group they
came from, with the expiry they had, which is why a refund is not simply "add credits back".

### `wallet.ledger_entries`

Every movement, in order, immutable.

```
id               uuid          PK
tenant_id        varchar(32)   NOT NULL
account_id       uuid          NOT NULL REFERENCES wallet.credit_accounts(id)
lot_id           uuid          REFERENCES wallet.credit_lots(id)
sequence_number  bigint        NOT NULL
direction        varchar(8)    NOT NULL   -- DEBIT | CREDIT
amount           integer       NOT NULL
reason           varchar(32)   NOT NULL   -- GRANT | BOOKING_CHARGE | BOOKING_REFUND |
                                          -- SESSION_EARNING | EXPIRY | PURCHASE | ADJUSTMENT
reference_type   varchar(24)              -- BOOKING | SESSION | PURCHASE | POLICY
reference_id     uuid
previous_hash    varchar(64)
entry_hash       varchar(64)   NOT NULL
occurred_at      timestamptz   NOT NULL DEFAULT now()

UNIQUE (tenant_id, sequence_number)
CHECK  (amount > 0)
CHECK  (direction IN ('DEBIT','CREDIT'))
INDEX  (tenant_id, account_id, occurred_at DESC)
```

Append only, enforced by a trigger that rejects `UPDATE` and `DELETE`. A correction is a new entry
with reason `ADJUSTMENT`; nothing is ever edited.

`entry_hash` covers the entry's own fields plus `previous_hash`, chained per university. Changing a
row behind the application's back breaks the chain from that point on, and a verification job finds
it. `sequence_number` is assigned by the application inside the transaction, not by a sequence,
because a sequence leaves gaps after a rollback and a gap looks exactly like a deleted row.

The balance is the sum of `remaining_amount`; the history is these rows. A test asserts the two
agree.

## `recognition`

Asking the university to recognise the hours taught. Ayni assembles the file; the university
decides.

### `recognition.rules`

```
id                    uuid          PK
tenant_id             varchar(32)   NOT NULL
minimum_hours         integer       NOT NULL
minimum_rating        numeric(3,2)
valid_from            date          NOT NULL
superseded_at         timestamptz
created_at            timestamptz   NOT NULL DEFAULT now()

CHECK (minimum_hours > 0)
```

### `recognition.requests`

```
id                  uuid          PK
tenant_id           varchar(32)   NOT NULL
student_id          uuid          NOT NULL
total_hours         integer       NOT NULL
sessions_count      integer       NOT NULL
average_rating      numeric(3,2)
status              varchar(16)   NOT NULL   -- SUBMITTED | UNDER_REVIEW | APPROVED | REJECTED
reviewed_by         uuid
reviewed_at         timestamptz
decision_reason     varchar(1000)
submitted_at        timestamptz   NOT NULL DEFAULT now()

CHECK (status IN ('SUBMITTED','UNDER_REVIEW','APPROVED','REJECTED'))
CHECK (status IN ('SUBMITTED','UNDER_REVIEW') OR (reviewed_by IS NOT NULL AND reviewed_at IS NOT NULL))
INDEX (tenant_id, status)
INDEX (tenant_id, student_id, submitted_at DESC)
```

`total_hours`, `sessions_count` and `average_rating` are copied at submission. The file a
coordinator reads must be what it was when it was submitted, not a figure that moves while they
review it.

### `recognition.request_sessions`

The sessions backing a request. **This is what stops the same hours from being claimed twice.**

```
request_id    uuid          NOT NULL REFERENCES recognition.requests(id)
session_id    uuid          NOT NULL
tenant_id     varchar(32)   NOT NULL
hours         smallint      NOT NULL

PRIMARY KEY (request_id, session_id)
UNIQUE (tenant_id, session_id)
```

`UNIQUE (tenant_id, session_id)` is the whole mechanism: a session can appear in **one** request and
never again. Credits are untouched and remain spendable, which is what you asked for: nobody is
punished for asking to be recognised.

## `reputation`

### `reputation.ratings`

```
id                 uuid          PK
tenant_id          varchar(32)   NOT NULL
session_id         uuid          NOT NULL
rated_by           uuid          NOT NULL
rated_user         uuid          NOT NULL
direction          varchar(24)   NOT NULL   -- STUDENT_TO_TUTOR | TUTOR_TO_STUDENT
stars              smallint                 -- only STUDENT_TO_TUTOR
was_punctual       boolean                  -- only TUTOR_TO_STUDENT
connection_ok      boolean                  -- only TUTOR_TO_STUDENT
session_flowed     boolean                  -- only TUTOR_TO_STUDENT
comment            varchar(500)
created_at         timestamptz   NOT NULL DEFAULT now()

UNIQUE (session_id, direction)
CHECK  (direction IN ('STUDENT_TO_TUTOR','TUTOR_TO_STUDENT'))
CHECK  (stars IS NULL OR stars BETWEEN 1 AND 5)
CHECK  ((direction = 'STUDENT_TO_TUTOR') = (stars IS NOT NULL))
```

The two directions ask different questions. A student says how good the tutoring was; a tutor
reports whether the other person turned up on time, whether the connection held and whether the
session could flow. The second is not an opinion about the person, which is why it is three facts
and not a score.

## `matching`

### `matching.available_offers`

The search reads only this. One row per hour a tutor is free for a skill they have enabled.

```
tenant_id          varchar(32)   NOT NULL
block_id           uuid          NOT NULL
tutor_id           uuid          NOT NULL
catalog_item_id    uuid          NOT NULL
starts_at          timestamptz   NOT NULL

PRIMARY KEY (tenant_id, block_id, catalog_item_id)
INDEX (tenant_id, catalog_item_id, starts_at)
```

It is denormalised on purpose. Without it, a search would have to join availability, enabled skills,
profiles and ratings across four schemas, which the module boundaries forbid and which would not
meet the response time TS07 asks for.

When several tutors are free at the same hour, several rows come back and the student picks, seeing
the rating of each. Fed by events from `booking`, `skills` and `reputation`.
